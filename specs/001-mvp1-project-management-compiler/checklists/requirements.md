# MVP1 Requirements Checklist

This checklist is the manual Spec Kit quality gate for the written MVP1
specification. `speckit` is not installed in the workspace, so the checklist is
maintained as a repository artifact rather than generated by a CLI.

## Completeness

- [x] User problem is stated.
- [x] Actors are identified.
- [x] User stories have priorities and independent tests.
- [x] Acceptance scenarios cover the source-to-model-to-export path.
- [x] Functional requirements have stable IDs.
- [x] Non-functional requirements cover determinism, safety, provenance, and environment restrictions.
- [x] Explicit non-goals prevent arbitrary GitHub interpretation and scope creep.
- [x] Success criteria are observable and testable.

## Architecture alignment

- [x] Local repository path is mandatory first-class input.
- [x] Optional HTTPS Git capture does not require live GitHub APIs.
- [x] IDEA-specific recognition is behind an extraction strategy.
- [x] DOC-07 is higher authority than Appendix, Gantt, or Kanban renditions.
- [x] Work package, delivery card, and milestone are distinct entities.
- [x] Parent effort is not added to child effort.
- [x] Dependency CPM is distinct from single-coder/resource scheduling.
- [x] Baseline is preserved separately from calculated analysis and forecast.
- [x] CARIO mapping is configuration-driven and unresolved values are visible.
- [x] All views derive from one canonical project model.

## Safety and truthfulness

- [x] No actual progress is inferred from repository activity.
- [x] Overdue is derived from date and authored state.
- [x] Unknown/blocked/not-run/unresolved states are explicit.
- [x] Native CARIO import is not claimed.
- [x] No external packages, Docker, database, AI parser, or enterprise auth are required.
